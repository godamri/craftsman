# Core Lifecycle & Delivery Contract

This document defines the universal state machine, compilation loop, delivery bundle requirements, and publishing outputs for Gen-Craftsman artifacts.

---

## 1. The 5-Phase Artifact Compiler Loop

Gen-Craftsman treats artifact synthesis as an iterative compilation pipeline:

```text
  ┌─────────────┐
  │ 1. DISCOVER │  Audit host environment, runtimes, package managers, and disk constraints.
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │   2. PLAN   │  Compile user intent into BaseArtifactSpec + Domain Spec (scenes & budget).
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │  3. CRAFT   │  Scaffold modular project, write declarative source code, run headless render.
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │  4. VERIFY  │  Execute Tier 1 technical validation + Tier 2 visual quality review.
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │  5. REFINE  │  Apply targeted patches; generate out/title.txt & out/caption.txt; package bundle.
  └─────────────┘
```

### Phase 2 Planning Rule: Theme Default Decision Gate
During the **PLAN** phase, the compiler must evaluate user intent against the **Theme Default Contract**:
1. **Default Visual Theme**: **LIGHT MODE**.
2. **Pre-Rendering Gate**: Ask internally:
   > *"Did the user explicitly request dark mode?"*
3. **Evaluation**:
   - If **NO**: Set `theme.mode = "light"` with clean white or warm neutral background (`#FFFFFF`, `#F8FAFC`, `#FDFBF7`), readable dark typography (`#0F172A`), and subtle elevation shadows. Technical subject alone is **NOT** a justification for dark mode.
   - If **YES** (explicit triggers: *"dark mode"*, *"dark theme"*, *"black background"*, *"cinematic dark"*): Set `theme.mode = "dark"` with deep solid canvas tokens (`#080B11` or `#0B0F19`).

## 2. Universal Lifecycle State Machine

Every artifact moves through six discrete operational states. Progression between states requires verifiable evidence.

```text
┌─────────────┐
│  SPECIFIED  │  Spec JSON written and validated against BaseArtifactSpec + Domain schema.
└──────┬──────┘
       ▼
┌─────────────┐
│ SCAFFOLDED  │  Project tree initialized; configuration and dependencies installed.
└──────┬──────┘
       ▼
┌─────────────┐
│ IMPLEMENTED │  All scene components, styles, and master compositions written in src/.
└──────┬──────┘
       ▼
┌─────────────┐
│  RENDERED   │  Headless compiler finishes; binary file generated in out/.
└──────┬──────┘
       ▼
┌─────────────┐
│  VERIFIED   │  Tier 1 technical checks PASS; Tier 2 visual inspection evidence generated.
└──────┬──────┘
       ▼
┌─────────────┐
│  PACKAGED   │  Complete Delivery Bundle assembled (out/artifact.mp4, out/title.txt, out/caption.txt).
└─────────────┘
```

### State Promotion Rules
- **Implemented $\to$ Rendered**: Requires compiler exit code `0` and a non-empty binary in `out/`.
- **Rendered $\to$ Verified**: Requires all Tier 1 technical invariant assertions to pass and Tier 2 inspection frames to be extracted into `report/frames/`.
- **Verified $\to$ Packaged**: Requires `out/artifact.mp4`, `out/title.txt`, `out/caption.txt`, `report/manifest.json`, and `report/validation-report.md` to be fully populated and finalized.

## 3. The v0.1 Delivery Bundle Contract

An artifact generated by Gen-Craftsman is **NOT** just a video file. A complete, successful generation must output the following directory layout:

```text
<artifact-project-root>/
├── artifact.spec.json         # Authoritative generation contract (Base + Domain)
├── src/                       # Editable, human-readable source code
│   ├── scenes/                # Modular scene components
│   ├── components/            # Reusable visual primitives
│   └── assets/                # Local static assets (SVGs, icons, audio)
├── out/                       # Compiled deliverables for publishing (3 files)
│   ├── artifact.mp4           # 1. Master media artifact
│   ├── title.txt              # 2. Human-crafted video title
│   └── caption.txt            # 3. Human-like casual publishing caption
└── report/                    # Observability and validation evidence
    ├── manifest.json          # Machine-readable generation metadata
    └── validation-report.md   # Technical audit log and inspection evidence links
```

> [!IMPORTANT]
> **Delivery Invariant**: An artifact is strictly **INCOMPLETE** if any of the following elements is missing:
> 1. **Final Binary** (`out/artifact.mp4`)
> 2. **Publishing Title** (`out/title.txt`)
> 3. **Publishing Caption** (`out/caption.txt`)
> 4. **Editable Source** (`src/`, `package.json`, project configs)
> 5. **Generation Metadata** (`report/manifest.json`)
> 6. **Validation Evidence** (`report/validation-report.md` + extracted frames)

## 5. Publishing Deliverables Contract (`out/title.txt` & `out/caption.txt`)

Every generated video artifact must compile three final assets into `./out/`:
1. `out/artifact.mp4` — Master rendered video binary.
2. `out/title.txt` — Human-crafted video title.
3. `out/caption.txt` — Human-written casual social/platform caption.

---

### Part A: Publishing Title Contract (`out/title.txt`)

```text
./out/title.txt
```

#### Title Format & Tone Rules
- **Human Educator Voice**: Crafted like a developer sharing an insightful lesson or YouTube Short.
- **Length**: 4 to 10 words. Concise, clear, and focused.
- **Content**: States the problem, mechanism, or mental model clearly without sensationalism.
- **Plain Text**: Single line, Title Case or clean sentence casing, zero surrounding quotes.
- **Zero Generic AI Clichés**:
  - ❌ *"The Ultimate Guide to Understanding Databases"*
  - ❌ *"A Comprehensive Deep Dive into Concurrency"*
  - ❌ *"Mastering the Art of Distributed Consensus"*
  - ❌ *"Unlocking the Secrets of Hash Maps"*

#### Exemplar Titles
- `How Databases Find Your Data`
- `Why Two Withdrawals Can Lose Money`
- `How Distributed Servers Agree on Reality`
- `What Happens When Hash Keys Collide`

---

### Part B: Publishing Caption Contract (`out/caption.txt`)

```text
./out/caption.txt
```

#### Caption Format & Structure
The file contains a short, human-written caption followed by an empty line and relevant educational hashtags:

```text
[short natural sentence]

#hashtag1 #hashtag2 #hashtag3 ...
```

#### Caption Writing Rules
- **Human Voice**: The caption must feel written by a real person sharing something they built or learned.
- **Short & Focused**: 1 short natural sentence. Do NOT explain or summarize the entire video.
- **No Marketing Fluff**: Avoid promotional language, corporate announcements, and hype.
- **No AI-Generated Clichés**: Strictly avoid generic descriptive openers such as:
  - ❌ *"Explore the fascinating world of..."*
  - ❌ *"Discover the power of..."*
  - ❌ *"Unlock the secrets of..."*
  - ❌ *"In this video, we will dive into..."*
- **No System/Pipeline References**: Never mention pipelines, validation, rendering engines, or AI artifacts.

#### Hashtag Rules
- **Quantity**: Include **3 to 8** relevant hashtags.
- **Topic Alignment**: Hashtags must match the actual technical topic being taught.
- **Educational Preference**: Prefer specific educational and engineering tags (e.g. `#mysql`, `#database`, `#concurrency`, `#backend`, `#softwareengineering`).
- **No Spam**: Avoid generic engagement bait tags (e.g. `#viral`, `#foryou`, `#trending`, `#fyp`).
- **No Irrelevant Trends**: Avoid unrelated trending tags.

#### Exemplar Captions

##### Example 1: Database Index Explainer
```text
why databases don't always search everything.

#mysql #database #backend #programming #softwareengineering
```

##### Example 2: General Database Explainer
```text
behind the scenes of every app storing your data.

#database #backend #technology #coding
```

##### Example 3: Concurrency Race Condition Explainer
```text
what happens when two users click withdraw at the exact same millisecond.

#concurrency #databases #backend #sql #coding
```
